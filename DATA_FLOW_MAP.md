# Data Flow Map

Current ShopMy limitation: the public Order Report has no click-token/click-ID
field. The official adapter therefore imports provider orders with
`order_attributions.click_token = null`; any token-linked attribution described
below is schema capacity for a future, explicitly approved rail, not a proven
ShopMy data flow. B-SHOPMY remains blocked.

Account-deletion provider boundary: RevenueCat succeeds only on an exact
`200` response whose app-user ID matches and whose `deleted` flag is true;
`404` is unattested and blocks. PostHog accepts only an exact typed `202`:
zero matches are already absent, while a fully queued nonzero deletion returns
pending and stops local storage/Auth erasure until durable status polling can
confirm completion. Apple is `revoked` only after exact token and revoke `200`
responses with an explicit client ID equal to the iOS bundle identifier.
Missing/unusable Apple credentials or automatic failure permit account
deletion and return a typed manual result; the app queues one in-memory iPhone
Settings notice before local sign-out. Durable provider-step state, Apple
refresh-token storage and credential-revoked notification, durable notice
recovery, PostHog polling, late-write suppression, and live proof remain open;
the overall flow is not yet durable, retry-safe, or race-free.
