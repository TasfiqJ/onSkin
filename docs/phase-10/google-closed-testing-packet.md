# Phase 10 Google Closed Testing Packet

Status: BLOCKED until Play Console evidence is attached.

## Platform Facts Used

- Google recommends internal testing before broader closed testing.
- Newly created personal Play developer accounts must run a closed test with at least 12 opted-in testers for 14 continuous days before applying for production access.
- First production release cannot rely on a rollout percentage; Android first-launch control must use country selection and traffic control.
- Play Console pre-launch reports and Android vitals are required launch-health inputs.
- License testers are separate from real willingness-to-pay evidence.

## Internal Test Checklist

- Install from internal track.
- Complete onboarding and account flow.
- Add catalog products through barcode/search/manual fallback.
- Trigger first value.
- Complete routine check-off.
- Try notification and camera permissions.
- Use Pro/paywall, purchase, entitlement, restore, and manage subscription with license testers.
- Find deletion/export controls.
- Review pre-launch report before closed test expansion.

## Closed Test Checklist

- Tester list includes real target users, not only passive accounts.
- If the account is a new personal account, keep at least 12 testers opted in continuously for 14 days before production-access application.
- Track opt-in date, first install date, first value date, and completion status.
- Separate license-tester QA from any cohort used for willingness-to-pay signal.
- Review Android vitals and Sentry release health before adding each wave.
