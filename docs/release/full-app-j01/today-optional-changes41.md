there is no confirmed entry. No change to report is a separate affirmative
owner action. The observed local date and recorded timestamp remain separate.

## One-key local transaction

Only existing encrypted layerwell.completions.v1 is used. Opt-in v4 contains
completionBytes (the exact prior completion JSON or null) and an immutable owner
journal. Legacy ordinary reads do not write. A note-only append leaves every
original completion byte intact; original completion mutations validate and
update the inner v3 state while retaining the journal. Remote journal/outbox/
terminal/unsynced and routine/step IDs retain their original semantics. No new
key, route, launch flag, dependency, network/provider payload or telemetry.

The note transaction compares exact source bytes as well as content proof and
expected revision. Stable IDs support exact retries; changed factual content,
source or lineage refuses. Canonical committed readback is required before a
saved result. The hash is a content identity, not a signature or truth proof.
PrivateKV remains the encrypted serialized mutation boundary; existing owner,
account-generation and health leases remain immutable and unmodified.

The UI captures the original lease and editor lifetime. Account/health changes
mask text and drafts; old callbacks cannot acquire a successor grant. Loading,
refusal, cancellation and unconfirmed writes are distinct. No note bodies in
error diagnostics. Browser/source proof does not qualify process-death/power-loss
or native filesystem behavior on a signed device.

## Existing export and deletion contract

shelf_and_routine.completion_and_sync_state. Its recursive sanitizer removes
ownerUserId fields; content, dates, lineage and hashes remain part of an explicit
owner-requested local-device export. Existing generic export is not a new import,
cloud restore, sharing or portability contract. Uninstall/key loss may lose
local content; previously exported copies cannot be revoked.

localPrivateDataKeys.ts already registers this key for full private-data deletion
and its encryption key for destruction. Health-purpose key registry already
includes it. Withdrawal/account isolation close authority and drain operations
