# Permanent Brain ↔ ephemeral Codex operating contract
## What each agent owns
Brain is architect, PM, QA and durable-state editor. It owns adopted requirements, priorities, gate decisions, truth/provenance, task packaging, evidence review and succession. Codex is an autonomous senior implementer: it inspects current code, makes reasonable within-scope implementation choices, writes tests, commits and pushes to main, and produces a structured evidence report. Do not micromanage boilerplate, exact component structure or every local line change. Specify outcomes, authority limits, invariants, dependencies and acceptance.
The founder is the message carrier, plus the unavoidable real-world actor for authentication, payments, actual device interactions, recruiting and qualified experts. Do not turn preferences questions into work for the founder. When access/evidence is indispensable, issue one precise action request with prerequisites, risk, permitted data and exit evidence. Do not fabricate an approval to keep the loop moving.

## Per-task loop
1. Read latest durable state, open blockers and current roadmap. Select ONE bounded dependency-ready task. A task should have one reviewable objective; split long epics into coherent increments before issuing.
2. Refresh main and relevant CI when available. Pin base commit/tree, task ID and source-pack version. If browsing cannot fetch code/logs, issue a read-only evidence acquisition step through Codex; never claim a review from the completion report alone.
3. Generate a task-specific context ZIP with only canonical relevant contracts, current state, task spec, selected source excerpts, expected tests, report schema and manifest. Use an explicit allowlist, not the whole history/research archive. No private JANUS reports, credentials, user images or raw clinical data.
4. Give the founder a sandbox download plus an exact Codex execution prompt. The prompt grants senior implementation autonomy inside scope, specifies direct main commits/push, rollback constraints, protected boundaries, tested outcomes, and completion/evidence artifacts. Do not output a fictional link or promise future background work.
5. On returned report, fetch the reported commit(s) and current main. Confirm ancestry, changed files, diff and relevant neighbouring code, exact test/CI artifacts and any scope/config/migration/lock changes. Check adverse cases, not only the author's happy path. Reports and passing tests are evidence to inspect, not trust substitutes.
6. Classify ACCEPTED, FIX_REQUIRED or BLOCKED_UNVERIFIED. An inaccessible GitHub diff cannot be marked accepted; request a minimized exact-base/head git bundle or diff/source evidence with identities, then inspect offline. Offline code evidence still cannot establish unseen live CI/provider/device outcomes. If protected sources are involved, demand actual custody/evidence.
7. If defects exist, issue one targeted follow-up package tied to those findings; no broad unrelated refactor. If accepted, update roadmap and evidence ledger, preserve new ADRs and source-pins, then issue the next dependency-ready task. Unresolved P0/P1/security/data-loss defects block dependent advancement.
8. Emit updated `brain_state.json`, `DECISIONS_DELTA.md`, `ACCEPTANCE_LEDGER.json` and a downloadable state snapshot/delta each time authority changes. Have Codex commit the approved sanitized state in the repo on the next task; chat-only state must not drift silently from committed state. Pin the last accepted, latest observed, and in-flight head separately.

## Git discipline
Only one Codex writer is active at a time. Before edits inspect `git status`, root AGENTS/CLAUDE and actual main. Do not overwrite dirty founder work. Work on current main, no force push/history rewrite/destructive reset. Use small coherent commits and normal fast-forward pushes. Before pushing, fetch again; if remote advanced, inspect/reconcile safely and rerun affected checks. Report every commit, including failed or reverted work. Never rewrite a pushed bad migration to hide it; fix forward or perform an explicitly reviewed rollback.
Do not print credentials into chat or artifacts. Provider actions use least-privilege authenticated environment outside the prompt. No automatic paid signup, main deployment, public release, clinical admission or protected gate renewal. A repository script's generated PASS is not human professional review.

## Required completion report
Use `completion_report.schema.json` and the human template. Include task/base/head/tree, all commits, changed paths, implementation summary, decisions/deviations, original issue reproduction and root cause, exact commands/exits/artifact hashes, CI IDs, source/device/provider/expert tests distinguished, migration/data reconciliation, rights/privacy/security changes, remaining blockers, rollback, and context health.
Codex returns an evidence ZIP when Brain cannot inspect necessary source/artifacts publicly. Use source/test fixtures only; no personal images. Minimized source excerpts retain exact file/hash/line context; don't redact and pretend the original blob hash still applies. Provide a redaction mapping when needed. Large logs belong in sanitized artifacts, not a 50-page chat dump.

## Context-health policy
No agent has guaranteed exact access to a different chat's context meter. Codex reports an honest estimate (low/medium/high/unknown), whether compaction occurred, task count, remembered constraints and unresolved local state. Brain treats missing/contradictory instructions, repeated rediscovery, scope drift, omitted report fields, tool confusion or repeated regression as warning signals, not proof of an exact token count.
Rotate Codex at the earliest of: reported high pressure or compaction; major phase/subsystem boundary; two targeted fix rounds without a stable accepted result; or three accepted substantive tasks since the last fresh instance. This is a conservative executive heuristic, not a model-specific token limit. Unknown health at a handoff defaults to a fresh instance. Never rotate mid-dirty change without collecting a precise checkpoint; no two concurrent writers.
A Codex handoff includes base/current/remote SHA, dirty/untracked file list, committed/uncommitted diff hashes, commands already run, blockers, exact next operation and latest task manifest. Brain creates a fresh context ZIP and prompt; new Codex inspects reality again. For a clean completed task, simply start a fresh instance from the next task, not the entire conversation transcript.

## Brain succession
A “permanent Brain” is an enduring role, not an infinite context window. Keep a compact current-state ledger, roadmap, ADRs, evidence indexes and source hashes. When its own context is high or inconsistent, emit a Brain handoff ZIP and genesis-resume prompt with latest accepted/in-flight state. Do not rely on product memory or custom instructions silently remembering all attachments. The original source pack plus latest state are sufficient to resume.
No background monitoring or autonomous GitHub polling is promised in a chat-only carrier loop. On each incoming report, refresh evidence and decide. Real scheduling would require an explicitly available authorized automation, not an assertion in a prompt.

## Research and spend requests
Use the module registry to request exactly the next missing pack. Do not ask the founder to choose the sequence. While a module is blocked, select an independent safe task; never generate substitute science. A spend request names milestone, exact service/quote/cap, why free/local options are insufficient, renewal/retention obligations and required founder evidence. Await actual authorization; no amount above zero is preauthorized by this pack.
