## Status Rules

Allowed statuses are `not-started`, `investigating`, `implemented`, `verified`, `blocked-external`, and `not-applicable`.

- No optimization item is initially `verified` merely because repository checks pass.
- `implemented` requires a complete code/configuration path but may still lack required acceptance evidence.
- `verified` requires the exact proof named by the plan.
- `blocked-external` is used only for a precise external dependency, not for difficult or incomplete local work.
- Every pre-existing dirty-worktree change is user-owned and remains unverified until reviewed against the current diff and acceptance contract.
