| `account-deletion`    | User JWT required; POST-only execution | Missing auth is 401; valid-JWT non-POST is 405 before deletion work; oversized bodies are rejected by `USER_EDGE_BODY_MAX_BYTES` before auth/body parsing; caller can delete only self. RevenueCat deletion succeeds only on an exact `200` body attesting the requested app user and `deleted=true`; `404` is unattested and blocks. A usable Apple authorization code triggers automatic token exchange/revocation only when explicit `APPLE_SIWA_CLIENT_ID` exactly matches `APP_IOS_BUNDLE_IDENTIFIER`. Only exact token and revoke `200` responses report `revoked`. A missing/unusable code, invalid configuration, exchange/no-token failure, or revoke failure cannot withhold deletion: the caller receives typed `manual_revocation_required`, logs contain only a stable sanitized reason, and the mobile app queues a one-shot in-memory iPhone Settings notice before local sign-out. PostHog accepts only an exact typed `202`; zero matches are `already_absent`, while a fully queued nonzero deletion returns `POSTHOG_DELETION_PENDING` and stops local storage/Auth erasure. Apple/PostHog/RevenueCat calls use timed fetches and bounded response reads; provider/storage failures do not return false success. Durable provider-step state and PostHog polling, late webhook/stale-session suppression, secure Apple refresh-token storage, Apple's credential-revoked notification, durable notice/status recovery, and live provider/device proof remain open, so the full lifecycle is not yet retry-safe or race-free. |
