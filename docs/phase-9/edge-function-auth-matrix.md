| `account-deletion`      | Mixed boundary; POST-only handler with gateway JWT verification disabled | `verify_jwt = false` is required because one handler serves four deliberately different lanes; it is not public authorization. `begin` requires a verified bearer JWT, derives the user only from Auth, applies the account/idempotency rate limit, and returns `202` plus no terminal-success claim. `preflight` requires a verified bearer JWT, validates its canonical owner before invoking the service-role opaque barrier RPC, and returns exact `{status:"clear",ownerSubject:<authenticated UUID>}` or `{status:"active",ownerSubject:<authenticated UUID>}`. The client rejects a cached session-user mismatch and uses that response subject for local/vendor publication or owner-conditional cleanup. Only the exact lane-specific `401 {error:"ACCOUNT_DELETION_SESSION_REJECTED"}` is authoritative invalid/stale bearer rejection; gateway, malformed, Auth transport, rate-limit, `5xx`, and barrier-RPC failures remain unavailable and retryable. `status` requires an exact opaque 256-bit capability, reveals only the bounded public operation/receipt view, does not create limiter rows for random misses, and rate-limits valid capabilities. `work` requires the dedicated 64-character lowercase-hex secret in `x-account-deletion-worker-secret`, compares it in constant time, returns 401 for missing/wrong values before worker execution, and returns only a bounded aggregate report. Non-POST is 405 and oversized input is 413 before lane work. Durable barriers, leases, encrypted provider state, no-blind-redispatch reconciliation, locked Storage/service-row re-attestation, at-most-once Auth deletion, receipts, and tombstones fail closed. RevenueCat uses REST API v2 only: `REVENUECAT_V2_SECRET_API_KEY` is mandatory, a V1 key cannot satisfy deletion, and the key is limited to project/customer read plus customer read/write. Apple fixed-origin token exchange must bind the returned identity to the authenticated Apple subject; only an exact successful exchange and Apple's exact `200` no-body revoke response may report automatic revocation, otherwise the durable result is manual revocation required. Required-mode PostHog persists the target set and dispatch boundary, reconciles async status, and requires two interval-separated absence observations plus exact no-recordings/capture-shutdown evidence. `EdgeRuntime.waitUntil` is intake acceleration only; the one-minute Vault-backed Cron `action: work` lane is authoritative. The account-deletion row names all four current lanes explicitly. Its existing
database leases are worker claim/reconciliation leases; they are **not** a
client session/provider publication lease. The `preflight` account lock ends
before mobile session publication and RevenueCat configuration, so the
two-phase publication fence in the account-deletion operations runbook remains
an open source release blocker. Live evidence cannot waive that race.

Strict Phase 9 signoff requires `phase9:live-edge-auth:strict` evidence for missing/invalid user JWTs, valid-JWT non-POST rejection across all user-JWT Edge Functions, oversized-body `413 payload_too_large` rejection across body-parsing user-JWT functions, malformed authenticated catalog/subscription requests, and deployed parity for provider timeout/response-size settings; `phase9:live-data-rights:strict` evidence for caller-only data export/delete, malformed photo-path omission, exported photo signed-URL expiry, data-export lifecycle fail/retry behavior, `429`/keyed-hash limiter behavior, and the complete durable deletion begin/status/receipt lifecycle; reviewed scheduler evidence for missing/wrong/correct account-deletion and health-consent `action: work` secrets, one-minute Cron continuity, bounded work reports, queue-age/lease/expiry monitoring, no service/provider call on unauthorized work, and epoch-owned Storage cleanup before terminal health withdrawal; `phase9:live-consent-withdrawal:strict` evidence for deployed granular revocation cleanup and the durable health-consent lifecycle; `phase9:live-public-forms:strict` evidence for public Turnstile, oversized-body no-write behavior, and 429/keyed-hash limiter behavior; `phase9:live-catalog-rate-limit:strict` evidence for catalog `429` behavior and redacted keyed-hash limiter samples; `phase9:live-order-report-poll:strict` evidence for scheduler-secret enforcement without authorized ShopMy polling; plus live negative tests for wrong-user access, webhook non-POST rejection, webhook signature failure, stale webhook signature, oversized webhook body rejection, duplicate webhook delivery, RevenueCat entitlement/tombstone lifecycle transitions, RevenueCat raw-payload minimization, Apple subject/revocation contracts, and redacted log review. Static and local rehearsal passes cannot substitute for these hosted tests.
