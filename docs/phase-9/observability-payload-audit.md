# Phase 9 Observability Payload Audit

## Sentry

The app initializes Sentry with `sendDefaultPii: false`, failed request capture disabled, screenshots disabled, view hierarchy disabled, performance tracing disabled, and breadcrumbs disabled. `setSentryUser` uses a pseudonymous account ID. `captureException` passes context through `sanitizeObservabilityContext` before sending `extra`, and passes the throwable through `sanitizeCapturedException` so Sentry receives a generic `redacted_exception` instead of raw exception messages, causes, or attached fields. The context contract admits only `source: phase2-runbook`; tags admit only `app_environment: development|staging|production`; user identity admits only `u_` plus 32 lowercase hexadecimal characters. Numeric, boolean, array, nested, accessor-backed, unknown, and arbitrary string context is rejected because no current producer needs it. Exception types are limited to fixed built-in JavaScript error classes. When the original error exposes an own data-property stack, the throwable scrubber retains only generated-bundle path/line/column tokens and drops raw function names, modules, messages, and other paths. The global `beforeSend` hook constructs a new event from an explicit allowlist and strips request, context, transaction, fingerprint, log entry, thread, span, module, measurement, server-name, SDK-processing, and transaction-source metadata before upload.

Only `apps/mobile/src/lib/observability/sentry.ts` may acquire the Sentry SDK, and that wrapper may call only `init`, `setTag`, `setUser`, and `captureException`. Phase 9 rejects runtime static, relative-to-`node_modules`, dynamic, `require`, import-equals, subpath, or re-export acquisition elsewhere; another SDK method; capture arguments that are not the exact sanitizer outputs; or drift from the fixed initialization options. Sanitizers inspect data descriptors without invoking ordinary getters and contain hostile and revoked proxy traps. URL/path/contact/health/free-text values and custom exception names therefore cannot become tags, extra, user identity, or exception text. Source-map and native-symbol recovery keeps only strict structural data: bounded generated-bundle frame paths, line/column/in-app fields, native instruction addresses, and validated Mach-O/source-map debug ID, address, size, and code-ID fields. Function/module symbols, unknown frame/image fields, and full native code paths are removed. The isolated source-audit matrix has one positive fixture and 14 bypass fixtures.

## PostHog

Analytics props are defined per event in `apps/mobile/src/lib/analytics/eventRegistry.ts`. `identify` sends only a pseudonymous account ID and no user properties. The tracker selects the named event's schema, reads only enumerable data properties without invoking accessors, and suppresses capture on an unknown/cross-event key, missing required key, invalid optional-key combination, impossible discriminator/count pair, or invalid value. Values are fixed enums, event-specific bounded integer ranges, opaque IDs, or constrained app/build versions; arbitrary compact tokens are not accepted.

The TypeScript tracker is derived from the same schema. The Phase 9 and Phase 10 source audit parses every production tracker import and call, requires literal events plus inline payloads, verifies nonliteral enum/undefined types, rejects diagnostic suppressions, proves the prepared payload is immutable and guarded before the sole PostHog capture, and requires at least one valid production emission for every registered event. Dynamic payloads, spreads, computed/duplicate keys, no-property payloads, cross-event keys, malformed/overlapping shape branches, parse errors, tracker escapes, and vendor-boundary decoys are blockers. The isolated analytics source-audit matrix has one positive matrix and 36 bypass fixtures. Product IDs, rule IDs, content IDs, quiz axes, skin profile outputs, local paths, barcodes, notes, OCR text, scores, arbitrary growth terms, and free text are not approved telemetry.

## Development Logs

Development/QA warning paths use `devWarn()` and `redactedErrorForLog()` so exception messages, stacks, URLs, tokens, paths, user IDs, and attached fields are not printed when PostHog, Sentry, or RevenueCat setup/capture paths fail.

## Release Requirement

Before public launch, capture live Sentry and PostHog payload samples from the exact release candidate and attach screenshots/JSON exports to the release-candidate folder. The Sentry recovery verifier rejects malformed release/dist, duplicate or invalid binary UUIDs, an invalid Hermes debug ID, and invalid verification time bounds before any provider request; successful verification returns the exact UUID/debug-ID inventory for release-contract comparison. Strict scripts still fail until `PHASE9_OBSERVABILITY_PAYLOAD_PASS=true`.
