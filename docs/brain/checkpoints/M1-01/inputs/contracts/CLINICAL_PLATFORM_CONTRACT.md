# Phone-only appearance-analysis platform — normative architecture
## Shared services, narrow modules
Capture is a reusable service, not duplicated in each J-module. A capture session can yield several feature inputs, but each module independently accepts/rejects its regions and each claim is independently admitted. J01–J13 primary report sections and J14–J27 derived/explanatory families are not 27 sensors. Never infer all outputs because one face detector succeeded.
Suggested interfaces (logical, not a forced code layout):
```ts
interface AppearanceModule {
  readonly descriptor: ModuleDescriptor;
  eligibility(input: CaptureManifest, context: EligibilityContext): Eligibility;
  analyze(input: PrivateArtifactHandles, context: RunContext): Promise<AnalysisResult>;
  summarize(result: AnalysisResult, policy: ApprovedExplanationPolicy): ReportFragment;
  compare?(a: AnalysisResult, b: AnalysisResult, context: ComparisonContext): ComparisonResult;
}
```
Registry discovery is static/allowlisted at build time. Modules cannot fetch arbitrary code or instantiate a hidden network model. A plugin describes its estimand, inputs/views/native resolution/capture policy, runtime/artifact versions, outputs/units, validation evidence, dependencies, limitations, consent purposes and device/OS/physical-camera support. Shared type contracts go into the existing packages/types boundary or a narrowly separated package; no cyclic mobile/backend imports.

## Records and reproducibility
A CaptureManifest includes owner/session ID, capture and ingest times, physical camera ID/lens, device model and physical-unit profile where required, OS/app/native build, original dimensions/orientation/mirroring, encoding/RAW class, colour space, exposure/gain/WB/focus, light state and actual monotonic timestamps, camera intrinsics/depth availability, view, quality diagnostics, consent-purpose receipt, capture policy/profile hashes and encrypted original artifact handles. “Unknown” metadata is null and may make a quantitative feature unsupported; it is not a zero or an assumed default.
An AnalysisRun records module ID, input manifest hashes, region/geometry/visibility schema, preprocessing, model weights/runtime/precision, threshold/postprocessing, measurement units/estimand, calibration, explanation/comparison policy, profile support, evaluation/admission manifest and private output artifact handles. Save masks/intermediates needed to reproduce the result, subject to lawful local retention. Do not save only a final score. Feature algorithm versions differ from app version; runtime conversion/OS/profile changes may invalidate prior validation.
A region result has status `valid`, `partial`, `retake`, `unsupported`, `not_measured` or `error`; a reason code; measured area/support coverage with denominator definition; typed values/units; and calibrated uncertainty or an explicit uncalibrated state. Null values are mandatory for unavailable results. Valid zero means a sufficiently observable region with no included target pixels above the validated detection limit, not proof of physical absence. Feature-level partial results cannot fabricate a whole-face total.
A ComparisonResult references two immutable runs, common support, registration error, policy compatibility, whether both originals were reprocessed, actual conditional noise calibration, display resolution and multiplicity policy. States: `detectable_change`, `no_detectable_change`, `not_comparable`. Percent relative change is withheld near zero and absent in the first release. No inference of product causality.

## Capture paths and physical limitations
Create a native iOS adapter for actual exposure/light/timestamp/RAW metadata and saved-image checks. A generic preview screenshot, stock image picker or Expo Go success is not proof of controlled acquisition. Keep ordinary photo diary available on supported app phones even when measurement profiles are unsupported.
Qualify rear physical-main RGB with an off–on–off torch experiment first for radiometric feasibility; qualify front RGB + screen fill as a separate convenience domain. The screen faces the wrong direction to illuminate a rear-camera face. Depth from a supported front sensor and rear LiDAR are distinct optional geometry inputs, not pigment depth or a prerequisite on every phone. Select two available/borrowed candidate iPhone profiles for the initial lab feasibility task, then declare only profiles whose actual evidence passes. Do not publish all-iPhone coverage or choose model names by guess.
Off–on–off must normalize exposure/gain/black levels, align geometry and interpolate ambient using actual timing. It does not magically remove motion, shot noise, glare, rolling shutter, flicker or an opaque computational ISP. Keep negative-difference QA diagnostics; do not clamp before checking failure. Distinguish sensor-linear RAW, computational RAW and processed RGB profiles. No beauty filter, generative cleanup, inpainting of hidden skin, gray-world skin whitening or per-channel minimum across different views.
View selection is predeclared by quality, not by whichever image has fewer spots. Initial three-view guidance is frontal and approximately ±30° oblique, with module-specific close-up when required. Initial 35–45cm distance/1000–1200 native face pixels/six-pixel target minima are pilot hypotheses, not universal guarantees. A physical phone-only self-capture must work without required external lamps/cards/stands; research calibration fixtures are allowed in the lab.

## Geometry and local measurements
Anatomical right/left is the person's right/left, independent of mirrored preview. Regions are hashed mesh triangles/barycentric assets or equivalently explicit reviewed geometry, not hard-coded screen rectangles. Store occlusion/exclusion and observable support separately from eligible anatomy. Exclude hair/eyes/lips/glare/shadows as the measurement policy requires. Do not erase red+pigmented overlap automatically.
Use declared image-projected area as the initial J05 metric. Surface-area claims require separate validation. Shared atlas pixels are coordinates, not uniform physical area. Select/deduplicate source support across views; never double-count cheek pixels. Union-of-valid-view A–H reporting must identify coverage and the exact projection aggregation; do not label it the entire anatomical face including unseen chin. If whole-face aggregation is not validated, show only validated regional results.

## Local storage, privacy and run cancellation
Analysis consumes private handles through owner-bound storage, not public URLs. Cancellation/sign-out/withdrawal/deletion increments the relevant generation and stops publication even if a native job finishes late. Intermediate caches, ML tensors on disk, debug images, thumbnails and exports follow the same deletion policy as originals. No images, masks, face embeddings or fine-grained results in analytics/crash dumps. Test network-disabled operation and error paths. Optional research transfer is a different purpose/consent pipeline with separate identifiers, access, retention and withdrawal rules; full-face images are not anonymous.

## Admission manifest and rollout
Maintain separate gates: G0 engineering arithmetic/fixtures, G1 capture/device qualification, G2 authorized target/data, G3 independent single-scan validation, G4 longitudinal change validation, G5 signed-build/claims/privacy/operations acceptance. A fixture pass can close G0 only. To display a single-scan value require G1/G2/G3/G5 for the exact supported profile and scope. To display change also require G4 and compatible common support. Expert judgement and independent data cannot be supplied by Codex.
Internal experimental runs must be unmistakably research-only and absent from normal user result screens. First external usability beta uses originals/diary and quality guidance with unvalidated measurements hidden. Clinical research participants may use a separately authorized research build/protocol; that does not grant consumer publication authority.
The kill switch narrows capability without deleting history or forcing an incompatible recomputation. For an update, reprocess both retained originals using one validated pipeline with consent, validate a bridge, or start a new numerical baseline. Otherwise retain photo viewing and state not comparable. No single global “AI ready” flag, no automatic skin-age admission.

## Plugin intake and downstream uncertainty
Each missing research pack must define the target, vendor-equivalence boundary, capture regime, rights/licences for code/weights/data, dataset/splits, annotation, baseline/candidate models, error/coverage/repeatability endpoints, study design, support policy, permissible wording and rollback. Only J05's full pack exists now. J14/J27 shared rendering can be built for J05's supplied semantics; new full-module summaries/advice need their own vetted definitions. Every derived value includes parent run versions; unavailable parents propagate unavailable values, not zero, inferred certainty or a complete profile code.
