# Source-bound finding reconciliation

Build a reusable deterministic reconciler within the authorized namespace. Input: actual provider artifact identity, scanner raw outputs and exact source/tool/rule identities. Output: each finding mapped to a retained record, a **proposed** new typed disposition with reproducible proof, or unresolved. Exhaustive count/set reconciliation must expose duplicates/omissions; a grouped summary alone is insufficient.

For secret findings, prefer original current-head GitHub artifacts. Keep history findings distinct from current-source findings. Existing accepted-history logic may be reused read-only, but a newly generated record cannot extend its authority. A public task-manifest hash can be proposed harmless only by reproducing the exact hash from its referenced committed input and binding the matched blob/range—not because it resembles64hex. Links, synthetic test values and public references need their actual typed source proof. Random or ambiguous values stay UNKNOWN. Do not use found credentials or run active credential-validation probes. Do not print, commit, upload or copy raw secrets into Codex context.

Analyze sanitized scanner outputs in place; publish only redacted identifiers, paths/ranges, rules, content hashes, classifications and proof references. A credible undisclosed credential triggers a precise owner security-action packet; no attempted authentication or history rewrite. Losing evidence through redaction must remain explicit, not fabricated as a hash match.

For npm/OSV findings, recompute exact dependency paths and distinguish shipped runtime, developer/build, and candidate-scanner exposure. Retain every raw advisory and scanner exit, current primary references and the actual graph. Re-execute existing legitimate mitigation tests where relevant; mitigation is not a new waiver. Current advisory retrieval may change; record snapshot/time and unknowns instead of blanket renewal. Existing expired exceptions remain expired.

For SAST, retain rule identity, reported severity, original outcome and exact blob. Proposed false-positive reasoning must be testable and reviewed, not a suppression list. Outside-source remediation is an inert file-specific diff plus reproducer, not active editing authority. Tests must reject a missing record, duplicate, wrong blob/range, public-digest lookalike, mismatched upstream advisory and fixture passed as a real scan.
