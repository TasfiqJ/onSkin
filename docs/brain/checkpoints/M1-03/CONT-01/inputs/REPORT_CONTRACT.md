# Exact evidence report
Use the existing strict M1 execution/continuation report shape with an explicitly anchored CONT-01 binding. Record original task base and continuation base separately, measured implementation SHA/tree and later evidence-only delivery separately, actual command/environment/source/tool/installation identities, UTC timestamps, exact exits/counts/skips and SHA256 hashes. State which dependencies were installed and which tests used that installation; an old shared install cannot prove a new lockfile.
Preserve failed controls and comparisons, refused gates, Windows limitations and missing Linux/native/provider facilities. A gate that stopped before a scanner is NOT_RUN/BLOCKED, not zero findings. Keep source-edit permission separate from G97/source/owner/provider/release acceptance. Record final actual CI/run/job/checkout identity; refresh after the delivery push, but report PENDING if unfinished rather than wait/retry indefinitely.
Keep raw safe evidence once under this checkpoint, index it from concise Markdown, and use exact paths/commits/hashes for historical evidence instead of copies. Do not publish credentials, personal faces, JANUS or raw clinical data. Store synthetic-only test evidence. Submission status stays SUBMITTED_REVIEW_REQUIRED/PARTIAL/BLOCKED, never ACCEPTED. Root handoff and safe push remain mandatory even with red CI.
