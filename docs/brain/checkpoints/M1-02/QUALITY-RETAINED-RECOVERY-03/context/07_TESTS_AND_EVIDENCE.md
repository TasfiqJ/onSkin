# Test, independent-falsification and UI evidence

- Before each real product change: source-bound reproduction and a negative check that fails on original code, plus exact regression suite passing after change. Do not call inability to mount/read a fixture a product test failure.
- Mandatory: Phase4 worklist check before/after, original positive and altered-input negative (disposable) check, focused tests for every changed path, broad impacted retained families, forced `npm run typecheck`, forced `npm run lint`, full `npm test` if feasible, `git diff --check` authored source and scripts. Run on a clean measured source HEAD where possible and record exact raw exits/paths/versions. Distinguish sparse checkout errors and external registry failures from real code failures.
- For UI changes: actually drive Expo web on supported viewport(s) using synthetic local-only development owners/fixtures, including denied/retry, offline/reload and A-to-B no-content-flash. Preserve compact screenshots and sanitized click/console traces. The existing E2E harness is READ-ONLY; an additive wrapper may live inside new checkpoint. Do not claim real OS/native paid/provider coverage.
- Record source SHA/tree and descendant evidence-only SHA/tree separately. Keep CI runs bound to the exact final pushed head, not an earlier commit; separately identify check success, skip, fail, and IN_PROGRESS. Never present original Security or Quality as green if not.
- Evidence: a structured completion report, README, RESULTS, TEST_MATRIX, source-scope Git/SHA256 manifest, CI diagnosis and open blockers. Keep logs bounded, exact bytes for critical errors, redact no raw secrets by refusing to capture them. Hash committed report entries and verify committed Git blobs/working bytes.
