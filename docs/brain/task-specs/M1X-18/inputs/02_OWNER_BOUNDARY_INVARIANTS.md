1. Owner identity is not merely a string: bind in-progress goals, raw quiz answers, and scored profile to the CURRENT health-processing authority (ownerUserId, accountGeneration, epoch generation, and revocation/expiry semantics). A→B→A must not inherit A's draft from an earlier admission even if the username and epoch number are the same. A same-owner regrant is a new health window. When no valid owner+health lease exists, return no private draft to ANY consumer and accept no private writes or navigation. Use the repository's established `healthDataWriteAdmission.ts`, `healthProcessingEpoch.ts`, account-generation and actual health consent contracts; do not invent a second global auth authority or weaken the underlying gates.
2. Cross-owner transition requires synchronous fail-closed provider publication and private state retirement. No old rendered function closure, queued React state update, timeout, delayed `persistSkinProfile` result, or async navigation may re-publish sensitive A state under B or resumed A. Tests must exercise old function references after revoke, including `setAnswer`, `toggleGoal`, `computeResult`, `persistSkinProfile`, and `reset` (reset can be safe-clearing; do not leak). Distinguish identity/health epoch retirement from focus-only screen retirement.

Missing consent, expired lease, owner mismatch, missing or ambiguous private-storage source, denied direct entry must fail closed without wrong-owner records. The existing local-first receipt and best-effort server mirror contract are immutable in meaning. If a protected storage layer cannot assure the requested operation, report a precise block, not a risky workaround. Clear raw pregnancy/sensitivity answers after valid scoring as the existing contract requires.
5. Mask private content during pending consent; keep appropriate accessibility announcements/usable controls and no flash of stale data.
