# Review checklist and evidence semantics

1. Identity: task/revision, authorized base, final HEAD/tree, append-only ancestry, clean or explicitly partial status. Hashes establish byte identity, not correctness.
2. Functional outcome: actual caller→domain→storage→restart→user-visible result. State exactly which path is synthetic, browser, native or provider-real.
3. Sensitive boundaries: owner/consent A→B→A, stale callbacks, revoked grant, exact original command, crypto custody, unknown outcome, read-only inspection, export, withdrawal/deletion priority and no resurrection.
4. Regressions: focused adverse cases, retained RED/GREEN, final-source type/lint/build/root receipts. Intermediate failures remain attributed to their actual source. Interrupted native final run is not the predecessor's completed result.
5. Runtime: declared finite first-attempt matrix, no hidden retry supervisor. Tested viewport ≠ physical-device accessibility.
6. Scope: unqualified positive capabilities inaccessible; no fake clinical, scientific, catalog, provider or professional facts.
7. Acceptance: source review, beta gate and full release are separate decisions; founder launch permission required.

Severity P0: actual/credible imminent privacy, destructive integrity or authorization exposure. P1: blocks a promised core journey or serious recovery/security defect. P2/P3: narrower nonblocking defects with documented mitigations. Do not downgrade a severe issue to pass a milestone.
