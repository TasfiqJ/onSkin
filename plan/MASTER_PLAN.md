# Master plan — from checkpoints to a demonstrable beta

## Diagnosis and correction
The prior process used increasingly long “finish everything” prompts, repeatedly sealed small checkpoints, and treated total test counts as the headline. Infrastructure and external approvals remained unresolved. Repeated historical audits consumed time while actual UI qualification stayed NOT_RUN. This plan fixes sequencing and evidence, not just prompt length.

The full intended product remains the original 38 requirements. Do not erase successful engineering or restart the codebase.

## Milestones and critical path
| Milestone | Outcome, not activity | Exit evidence | Owner |
|---|---|---|---|
| BR-000 | Existing E40 work safely adopted into one source of truth | Known live writer, exact checkpoint or preserved partial work, first GitHub return | Existing Codex; Brain reviews |
| BR-001 | A reproducible runnable core app, or a precisely actionable runner blocker | Same-source real-browser core journey with real storage and no external retry supervisor; finite first-attempt matrix | Codex |
| BR-002 | Cohesive consumer core with no release-blocking integrity defects | Manual intake → explicit routine → actual use → correction/history → reload → selected brief → export/withdrawal/delete | Codex; independent Brain review |
| BR-003 | Exact limited-beta candidate qualified for its exposed surfaces | Threat/privacy review, signed supported iPhone install, relevant DB/backend tests, accessibility, support/revocation and permissions | Brain + actual custodians/owner |
| BR-004 | Explicit small private-beta launch decision | Approved scope, cohort, data handling, exact artifact, support/incident plan and founder authorization | Founder after review |
| FULL | Original complete onSkin release | All38 plus all applicable original gates and explicit release approval | Original accountable owners |

BR-001 and BR-002 may be executed as one substantial authorized work package when the runner works. They are not a series of one-file tickets. The initial launch of BR-001 waits for E40 reconciliation and a clean reviewed base. Freeze a candidate for qualification rather than adding speculative architecture indefinitely.

## Separate tracks
- Core consumer beta candidate: highest-priority implementation and actual runtime qualification.
- Protected security/DB/native: explicit gate-owner work, not a permanent red footnote. Prepare a successor candidate without changing frozen historical truth.
- J01 scientific feasibility: acquire/authenticate research/rights, qualify capture, and evaluate a locked pipeline. Parallel research intake, not invented pore output.
- Professional, operator, payment, commerce and community: full-release backlog; promote only when needed for the approved beta or a shared critical dependency. Existing safeguards remain closed.

## Engineering decision policy
Codex owns design, implementation, refactoring and tests inside the authorized outcome. Brain specifies user outcome, boundaries, definition of done, dependencies and evidence—not every helper or algorithm. One active implementation package, one source writer. Read-only review may parallelize.

A work package ends with a complete outcome, a demonstrated external blocker after a bounded diagnostic budget, or a clean explicitly partial checkpoint at a real session limit. It does not end because one test passed, nor pretend to run after its session ends.

## Stop doing low-value work
No new feature or storage abstraction without a direct required user journey, demonstrated defect, or a recorded dependency for the current milestone. Long-history work already in E40 must be preserved and reviewed, but not allowed to indefinitely displace a functioning demo. Do not raise capacity constants or weaken tests as a shortcut. If existing safe limits suffice for a proposed bounded beta, record the limits and independently review that applicability; do not silently promise unlimited use.

## Blocker escalation
A repeated environment failure is not a reason for ten more coding campaigns. Run one bounded diagnostic packet on a materially changed environment; if blocked, record exact command/error, required capability, smallest owner action and impact. Brain handles the owner recommendation. Continue only independent high-value work, not unrelated filler.

## Progress reporting
Report: real core journeys independently demonstrated / planned; severe open defects; candidate build identity; evidence age; blocked owner decisions; deployed/exposed surfaces. Track tests as a regression signal, never percent product completion. Distinguish SOURCE_IMPLEMENTED, LOCAL_TESTED, RUNTIME_DEMONSTRATED, INDEPENDENTLY_REVIEWED, BETA_QUALIFIED and FORMALLY_ACCEPTED.

## No schedule fiction
There is no guaranteed launch date or overnight runtime. Forecast only after a runner and at least one real vertical journey have been measured. Preserve checkpoint/continuation records when platform limits stop execution.
