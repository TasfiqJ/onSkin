# Threat Model

## Assets

- Account identity: Supabase auth user ID, anonymous account state, OAuth identity, session tokens.
- Health-adjacent profile: skin profile result, goals, sensitivity, irritation, pregnancy-related flags if collected.
- Product shelf: products, ingredients, barcodes, OCR/labels, expiry/PAO, notes.
- Routine and adherence: AM/PM plan, cycle state, completions, ramps, reminders, streaks.
- Photos: raw captures, encrypted local photo files, metadata, notes, thumbnails, share/export cache files, optional cloud paths.
- Payments: RevenueCat app user ID, entitlement mirror, webhook payloads, reverse trial state.
- Consent/privacy: consent ledger, withdrawal, export/delete, analytics opt-out.
- Observability: PostHog events, Sentry context, local logs.
- Community/Ask/AI: consent, prompts if cloud Ask is enabled later, community notes/questions.

## Threat actors

- Unauthenticated internet user.
- Authenticated user trying to read/write another user's data.
- User with modified app bundle or intercepted network traffic.
- Attacker with stolen access/refresh token.
- Malicious or compromised webhook sender.
- Malicious catalog/OCR/community input.
- Prompt-injection attacker if cloud Ask/RAG is enabled.
- Insider/operator with logs or dashboards.
- Founder/operator misconfiguration.

## Trust boundaries

- React Native bundle is public and cannot hold private secrets.
- Supabase anon/publishable key is public; safety depends on RLS/storage policies.
- Edge Functions using service role must authenticate callers before touching user/payment data.
- Local device storage is attacker-readable on compromised devices; sensitive local records should be encrypted.
- Analytics/crash SDKs are third-party processors and must receive only minimized/redacted payloads.
