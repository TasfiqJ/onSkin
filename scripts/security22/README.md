# Current public technical candidate

Campaign23 repairs the current path; Campaign22 remains immutable historical
evidence. The source base is exact PR26, never a moving substitute. Diagnostics
publish fixed stage/predicate tokens only. Early refusals retain disclosure
controls and explicit NOT_RUN/INCOMPLETE components; unknown source/tool bindings
remain null. Interrupted attempted checks are INCOMPLETE. A failed native patch
check cannot erase a completed tooling result. Readiness remains nonzero.
Exclusive, fsynced progress records precede collection and retain completed
components even after a hard process stop. Their unfinished stability state and
null unestablished bindings are explicit. A completed run's index hashes both
the journal and the final individual component receipts.

The npm profile is a **fresh global npm 11.20.0 installation** in an isolated
prefix containing a regular Node 22 binary. CI provisions this prefix normally.
The authenticated public archive is
https://registry.npmjs.org/npm/-/npm-11.20.0.tgz, SHA256
`d1a92f40e6c407b84c3a00c3cf978a10b24fd42f153c527e2016cef7bb34a483`.
The independently derived expected inventory is pinned in toolchain.json and
its complete model digest is pinned in toolchain.py. POSIX requires all 1,943
archive files plus all nine declared internal executable links. Windows requires
all 1,970 regular files, including all 27 exact cmd-shim 8.0.0 generated files.
There are no optional observed subsets and `.bin` is never omitted.

All file names, contents, counts, bytes, directories and executable link targets
must reconcile with that fixed profile. Package bin declarations and regular
target hashes are checked; chained, undeclared, escaping, cyclic, dangling,
reparse and aliased entries refuse. Enumeration/read/stat failures and exhausted
bounds refuse explicitly. Stable before/after walks supplement the pinned
expected content; they do not establish completeness by themselves. Windows
path/fd stat executable-bit inference differs, so only those inferred bits are
normalized; file type, identity, size, timestamps and actual ACL reads remain
checked.
Windows Python 3.12 reports path and handle ctime in different clock domains.
Only cross-domain path/handle comparison uses birthtime; handle/handle raw
ChangeTime and path/path raw timestamps still detect mutations. Git uses its
native long-path support, and any diagnostic on stderr refuses enumeration.

The Windows deny-directory control uses a same-account restricted reader with
optional privileges disabled. It privately verifies account identity and exact
thread-token restoration. Public receipts retain only eight fixed boolean proof
fields; no token, SID or arbitrary error is published. A missing capability or
failed restoration is INCOMPLETE, and a denied enumeration is required before
the inventory refusal counts as a performed positive control.

Run `python -B scripts/security23/test_partial_results.py` and
`python -B scripts/security23/test_toolchain.py --regressions` in addition to
all inherited checks. Platform-specific counterparts are explicitly NOT_RUN
on the other OS, never counted as performed. The default test_toolchain.py
command runs the authenticated historical function and is labeled separately
from current positive proof and real component execution.

Run `python -B scripts/security22/test_security22.py` before collecting output.
Run `python -B scripts/security22/run.py` from a clean full checkout after
normal `npm ci`. Required public base/main refs must exist. Exit 1 is expected
while required findings or qualified custody remain unresolved; exit 2 means
an incomplete/refused execution. Component PASS has its own exact denominator.

The runner executes real npm/OSV and installed-source checks, mandatory native
patch checks and retained tooling regressions. It binds HEAD/tree, explicit
public refs and reachable Git metadata, every committed path/mode/object/size,
public working bytes, tool executables/npm tree/config/program digests, and
actual process exits. It repeats inventories after execution. It never infers
a scan from a wrapper step or accepts a supplied clean result. `verify
--receipt FILE` re-executes current checks and requires exact deterministic
evidence equality. It still cannot grant acceptance.

Use `--output-dir NEW_DIRECTORY_OUTSIDE_CHECKOUT` to publish each completed,
stable component separately with exact source/tool bindings and a hashed index.
The directory must be new, with regular parents; writes never overwrite files.

Archive handling is in memory, with no extraction: regular-member/name/mode
checks, parent aliases, bounded depth/count/expanded bytes/ratio, and explicit
unsupported/custody dispositions. Files over bounds refuse content coverage.
Committed binaries are inventoried and byte-bound, not described as text scans.
Historical M1-03 artifacts are metadata-only: their contents are not opened.
Full historical secret/static scans and original findings need qualified
custody and remain BLOCKED/NOT_RUN. This is deliberately incomplete coverage,
never a zero-findings result.

Ignored installed dependency roots have a separate full installed inventory;
other ignored content is explicitly incomplete. Staged, untracked, hidden-index,
link/reparse, changed or inaccessible source refuses. Subprocesses use bounded
streams/deadlines and process-tree containment (Windows gated job object;
POSIX owned process group). Diagnostics use an allowlist; raw output, exception
text, snippets, paths and secret-derived fingerprints are never public output.

The additive PR workflow leaves all original Security jobs unchanged and red
where they remain red. It has read-only repository access and no secrets,
production access or acceptance authority. Unit/synthetic controls are labeled
separately from real check executions. See docs/security/security22/ for causes,
repairs, validation and unresolved blockers.
